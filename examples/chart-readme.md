# Скорость моделей: chart.py

Заметки по замеру скорости моделей через [plusvibeapi.ru](https://plusvibeapi.ru/models) (октябрь 2026).
Цель — выбрать модель для агента с tool calling.

```bash
uv run python examples/chart.py
```

Нужен `.env` с `LLM_BASE_URL` и `LLM_API_KEY`. Список моделей и число прогонов (`RUNS`) задаются в начале скрипта.

## Как отбирали модели

1. Взяли каталог plusvibeapi.ru: 74 модели.
2. Оставили модели, у которых и input, и output стоят не больше 100 ₽ за 1М токенов. Jev 1.13/1.14 исключили: это decision-модели, они не работают через chat/completions.
3. Отсортировали по [Artificial Analysis Intelligence Index](https://artificialanalysis.ai/leaderboards/models), брали лучший режим reasoning каждой модели. В топ-10 вошли:

| Модель | AA Index | Input / Output, ₽ за 1М | Смешанная, ₽ за 1М | ₽ за пункт AA |
|---|---|---|---|---|
| kimi-k3.1-pro | 55 | 9,09 / 45,47 | 18,19 | 0,33 |
| gemini-4-argon | 53 | 15,84 / 79,20 | 31,68 | 0,60 |
| gpt-6.1-sol | 52 | 11,00 / 55,00 | 22,00 | 0,42 |
| grok-4.7 | 46 | 9,00 / 22,63 | 12,41 | 0,27 |
| mimo-v2.6-pro | 46 | 24,44 / 48,88 | 30,55 | 0,66 |
| qwen3.8-max | 45 | 5,28 / 15,84 | 7,92 | 0,18 |
| deepseek-v4.1-flash-1017 | 45 | 2,00 / 8,00 | 3,50 | **0,08** |
| glm-5.3 | 45 | 16,56 / 52,05 | 25,43 | 0,57 |
| claude-haiku-5.5 | 43 | 3,00 / 13,00 | 5,50 | 0,13 |
| minimax-m3.1-flash | 43 | 4,56 / 18,23 | 7,98 | 0,19 |

Смешанная цена считается как у Artificial Analysis: на 3 токена input приходится 1 токен output, то есть `(3 × input + output) / 4`. ₽ за пункт AA — это смешанная цена, делённая на AA Index; чем меньше, тем дешевле обходится каждый пункт «ума». Цена за токен не учитывает многословность: kimi-k3.1-pro тратит много токенов на скрытые рассуждения, поэтому реальный запрос у него дороже, чем видно по таблице.

Часть подходящих по цене моделей в AA не нашлась: GPT-6 Sol, GPT-5.6 Sol, GPT-5.6 Luna, DeepSeek V4.1 Flash без суффикса 1017, GLM-5.3 FlashX и другие. В рейтинг они не попали. Среди них есть кандидаты в топ: например, у GPT-5.6 Sol в июле было 59.

## Что меряем и почему

Метрики выбраны по тому, как их ощущает пользователь.

**Текстовый ответ** (стрим, промпт «Объясни в 3 коротких абзацах, что такое ReAct-агент…»):

- **TTFT** — время до первого видимого текста, то есть сколько человек смотрит в пустой экран. Для чата это главная метрика. Скрытые рассуждения модели сюда не входят.
- **Всего** — время до полного ответа.
- **Симв/с** — скорость печати после первого токена. Считаем в символах, а не в токенах: у моделей разные токенизаторы, а пользователь видит текст.
- **Символов / Токенов** — для контекста. Многословная модель дольше пишет ответ. Если токенов заметно больше, чем видно текста, модель потратила их на скрытые рассуждения.

**Tool calling** (промпт «Какая погода в Москве и в Париже, в Цельсиях?»): полный цикл, как в `CustomAgent`.

1. **Вызов.** Модель должна вернуть ровно 2 параллельных `tool_calls`. Аргументы проверяются pydantic-схемой `get_weather`, плюс сверяются города и `unit="c"`.
2. **Ответ.** Модель получает результаты инструментов и должна дать итоговый текст.

В агенте пользователь ждёт каждый шаг целиком, и шаги складываются. Поэтому здесь главная метрика — «Всего».

**Одинаковые условия:**
- У всех моделей один клиент, один промпт и одни и те же параметры.
- Запросы идут последовательно.
- Раунды чередуются по кругу (раунд 1 по всем моделям, потом раунд 2), поэтому колебания сети делятся между моделями поровну.
- В таблицах медиана по `RUNS` прогонам.

Выровнять не удалось одно: reasoning effort у каждой модели остаётся её собственным значением по умолчанию.

## Выводы

- **Для агента выбрали deepseek-v4.1-flash-1017.** У него самый быстрый цикл tool calling, он стабильно быстр во всех прогонах и самый дешёвый в топе (2 / 8 ₽, 0,08 ₽ за пункт AA — вдвое выгоднее следующей claude-haiku-5.5).
- **Запасные варианты:** minimax-m3.1-flash и grok-4.7. Grok один раз ответил ошибкой 400 и один раз отвечал 32 с.
- **Для чата, где важен быстрый первый текст:** claude-haiku-5.5 стабильно отвечает за ~2.5 с, но пишет многословно и медленно.
- **Лидер бенчмарков не значит быстрый.** У kimi-k3.1-pro AA Index 55, но он думает ~25 с перед первым словом и ~45 с тратит на цикл с инструментами.
- **gpt-6.1-sol через этот прокси не стримит:** ответ приходит одним куском.

## Оговорки

- **Разброс большой.** Одна и та же модель в разных прогонах выдавала TTFT 1.7 и 37.7 с: glm-5.3, gemini-4-argon, grok-4.7. Похоже на очередь или холодный старт на стороне прокси. Медиана из 1–3 прогонов ориентировочная, для решений лучше ставить `RUNS = 5` и больше.
- **Проверка tool calling строгая.** В настоящем агенте ошибка валидации вернулась бы модели, и gemini-4-argon, скорее всего, исправился бы со второй попытки, но это лишний шаг.
- **gpt-6.1-sol возвращает `content: []`.** Из-за этого `message.model_dump()` в `agent.py` выдаёт pydantic-предупреждение. Работе это не мешает.
